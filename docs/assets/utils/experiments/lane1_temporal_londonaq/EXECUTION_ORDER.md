# Execution Order -- Lane 1 Temporal LondonAQ

## Primary order (family-first within each tier)

```
Core tier (rates 0.1, 0.3):
  1. dl_benchmark_official_londonaq_mcar10_test
  2. dl_benchmark_official_londonaq_mar10_test
  3. dl_benchmark_official_londonaq_mnar10_test
  4. dl_benchmark_official_londonaq_mcar30_test
  5. dl_benchmark_official_londonaq_mar30_test
  6. dl_benchmark_official_londonaq_mnar30_test

--> Review core results before continuing

Stress tier (rate 0.5):
  7. dl_benchmark_official_londonaq_mcar50_test
  8. dl_benchmark_official_londonaq_mar50_test
  9. dl_benchmark_official_londonaq_mnar50_test

--> Review stress results
```

## Alternative: algorithm-wise order

For expensive DL methods, run one algorithm across all core recipes before starting stress:

```
Algorithm: BRITS
  1. mcar10 → mar10 → mnar10
  2. mcar30 → mar30 → mnar30
  --> Review
  3. mcar50 → mar50 → mnar50

Algorithm: SAITS
  1. mcar10 → mar10 → mnar10
  ...
```

The app supports filtering by family, rate, and role. Use the Plan Manager status filter or the preparation board recipe filter to scope execution.

## Execution policy

- Scientific DL execution lane required
- GPU preferred but CPU accepted with warnings
- Mock/demo execution NOT allowed for benchmark claims
- Each plan executes train → validate → test in lifecycle order
- Each plan uses the **dl_curriculum_v1** policy: curriculum-to-target training schedule, stable_validation_surface checkpoint selection
- Training loop schedule is deterministic and derived from the recipe rate (see `OFFICIAL_DL_BENCHMARK_GRID.md`)
- A plan created before dl_curriculum_v1 must NOT be reused as official thesis evidence — recreate from the rebased recipe book

## After-execution checks

Before comparing:

- All 9 plans executed (or at least all core plans)
- Each plan has test metrics
- Each plan has prediction artifacts
- Each DL plan has `runtime_summary_payload.best_training_loop` with `evidence_status == complete`
- Each DL plan has `training_loop_trace_path` and `selected_checkpoint_path`
- Comparison Studio shows compatible schema for intended comparison tiers
- Evidence drawer shows no blocked/danger items for compared results
