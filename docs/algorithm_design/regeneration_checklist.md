# AD4 Regeneration Checklist

Commands to regenerate all evidence artefacts before final delivery.
These require the full ImputeBench environment with `data/` and `scripts/` available.

## Regenerate design inventory (AD0)

```bash
imputebench audit design-inventory --format both --output-dir data/audits --docs-dir docs/algorithm_design
```

Writes to: `docs/algorithm_design/inventory/` (register, implementation matrix, evidence status).

## Regenerate card index (AD1)

```bash
imputebench audit generate-cards --format both --output-dir docs/algorithm_design/cards --overwrite
```

Writes to: `docs/algorithm_design/cards/`.

## Regenerate scientific conformance (AD1.5 + AD1.6)

```bash
imputebench audit conformance --format both --presentation-summary --output-dir data/audits --docs-dir docs/algorithm_design
```

Writes to: `docs/algorithm_design/protocols/conformance.md`, `docs/algorithm_design/status/conformance.md`, `docs/algorithm_design/conformance/`.

## Regenerate execution truth (AD2)

```bash
imputebench audit execution-truth --format both --output-dir data/audits --docs-dir docs/algorithm_design
```

Writes to: `docs/algorithm_design/status/execution_truth.md`, `docs/algorithm_design/cards/_execution_truth_badges.yml`.

## Regenerate comparison validity (AD3)

```bash
imputebench audit comparison-validity --format both --output-dir data/audits --docs-dir docs/algorithm_design
```

Writes to: `docs/algorithm_design/status/comparison_validity.md`.

## Pre-delivery checks

- [ ] `cards/index.md` lists the expected canonical 17 algorithms (no duplicates, no legacy entries).
- [ ] `status/conformance.md` shows clean verdicts (no `not_auditable` canonical entries).
- [ ] `conformance/presentation_summary.md` reflects current AD2 `execution_ready` status for all methods.
- [ ] `status/execution_truth.md` marks 17 methods as `execution_ready`.
- [ ] `status/comparison_validity.md` clearly identifies exploratory vs thesis-grade comparisons.
- [ ] No duplicate registry/test entries leak into supervisor-facing tables.
- [ ] EWMA Smoothing name is used (not "ExponentialSmoothing" without qualification).
- [ ] SAITS-LC/LCH documentation includes anti-double-conditioning and inference truth safeguards.
- [ ] `supervisor/summary_table.md` has exactly 17 rows (no more, no less).
