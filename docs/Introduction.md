# Introduction

**EviBench** is an evidence-centered research platform for reproducible machine-learning
experimentation across scientific domains — air quality, physics, chemistry, biology, and beyond.

The platform ships as a collection of domain-specific modules. **ImputeBench** is the first
production module, focused on missing-data imputation for temporal and spatial datasets.

This introduction covers the ImputeBench workflow. Future modules will follow the same
evidence-centered design: traceability, compatibility checks, and inspectable results.

---

## What ImputeBench helps you do

ImputeBench brings together the main parts of an imputation workflow in one place:

- prepare datasets, algorithms, masking assets, and benchmark assets,
- create and execute experiment plans,
- inspect results with both metrics and visual views,
- compare compatible outputs across runs and algorithm families,
- keep traceability strong enough for real analysis and real reuse.

In practice, imputation workflows become messy quickly: datasets evolve, masking setups
drift, runs accumulate, outputs lose context, and comparisons become harder to trust.
ImputeBench was built to make that workflow calmer, clearer, and easier to follow.

The goal is not only to run algorithms. The goal is to keep the full path readable: what
was prepared, what was executed, what was observed, and what can be compared with confidence.

## The main product areas

| Area | Role |
| --- | --- |
| Data & Algorithms | Register and inspect the core assets used by the workbench. |
| Experiment Runs | Prepare plans, attach execution context, and launch runs. |
| Results Navigator | Read one result in detail through metrics, artifacts, and visual analysis. |
| Comparison Studio | Build comparison plans, check compatibility, rank outputs, and review evidence side by side. |
| Thesis Evidence | Dashboard → Storyboard → Gate — the evidence export pipeline for thesis-grade work. |
| Benchmark assets | Manage shared contracts and mask banks used to keep comparisons aligned. |

Together, these areas form one continuous workflow rather than a collection of isolated tools.

## A simple way to think about the workflow

```mermaid
flowchart LR
    A[Prepare assets] --> B[Create experiment plan]
    B --> C[Execute run]
    C --> D[Inspect result]
    D --> E[Compare compatible outputs]
    E --> F[Assemble thesis evidence]
    F --> G[Export and reuse evidence]
```

This sequence is intentionally straightforward. You do not need to memorize the whole
system before becoming productive. You can enter through one task, then follow the next
visible step.

For thesis-grade work, the final two steps (assemble evidence → export) are covered in
detail in [`Thesis_Workflow.md`](Thesis_Workflow.md).

## Why the workflow stays practically credible

ImputeBench is designed to support comparisons that remain readable and defensible after
the run is over.

First, it keeps **traceability** close to the result. A result is not treated like a loose
score; it stays connected to its dataset, execution context, masking setup, artifacts, and
benchmark metadata.

Second, it treats **comparison compatibility** as a real concern. Not every result should
be compared just because two numbers exist. The workbench makes room for compatibility
checks, shared benchmark contracts, and shared mask banks so that comparison stays grounded.

Third, it gives room for **inspection, not only ranking**. Metrics matter, but they are not
the whole story. ImputeBench also helps you inspect reconstructed outputs, masked inputs,
deltas, and other artifacts that reveal how a method actually behaved.
