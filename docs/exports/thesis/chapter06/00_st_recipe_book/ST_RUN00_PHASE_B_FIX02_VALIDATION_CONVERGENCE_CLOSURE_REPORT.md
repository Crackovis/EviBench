# ST-RUN00-PHASE-B-FIX02 — Validation-Loss Policy and Convergence Strictness Closure

**Project:** EviBench / ImputeBench CLI  
**Phase:** B-FIX02  
**Depends on:** ST-RUN00-PHASE-B-FIX01  
**Precedes:** ST-RUN00-PHASE-C  
**Generated:** 2026-05-19  
**Decision:** `READY_FOR_PHASE_C`

---

## 1. Previous convergence state

After Phase B FIX01 all false-discovery blockers were cleared. The only remaining blocker was:

```
convergence_caveated_in_strict_mode
  reason: validation_loss_missing (all 4 algorithms)
```

The Phase B FIX01 convergence summary:

|---|---|---|---|

Phase B FIX01 final gate: `failed` / `scientific_ready=false`.  
Phase B FIX01 decision: `READY_FOR_PHASE_C_WITH_CAVEATS`.

---

## 2. Validation policy decision

**Option A implemented** — real per-epoch validation tracking as the default scientific profile.

```
validation_policy: masked_validation_support
validation_metric: masked_mse
requires_validation_tracking: true
```

A disjoint validation mask is carved from the observed (non-hidden) training support at 10% rate using seed 43. This gives genuine held-out loss supervision per epoch without contaminating the test hidden support.

The `train_only_convergence` fallback profile remains available for explicit declaration via `validation_policy=train_only_convergence`, but is not the default scientific profile.

---

## 3. Implementation changes

### `spatiotemporal_task_executor.py`

Added `STValidationSupport` dataclass and `_build_validation_support()`. For runs with `training_tier=scientific`, a masked validation tensor is synthesised and injected into `algo_config` under `_validation_split` / `_validation_split_original` keys. Validation support metadata is emitted as a `validation_support_metadata` outcome artifact.

### `result_persister.py`

Extended `_persist_st_lifecycle_artifacts()` and `_persist_st_prediction_artifact()` to write validation fields (`validation_policy`, `validation_metric`, `requires_validation_tracking`, `validation_support_fingerprint`, etc.) into `runtime_summary.json` and `metadata.json`.

### `scientific_training_tier.py`

Added optional fields to `STTrainingConfig`: `validation_policy`, `validation_support_fingerprint`, `validation_split_id`, `validation_mask_seed`, `requires_validation_tracking`. `to_dict()` / `from_dict()` updated to preserve these fields.

### `training_convergence.py`

Updated convergence semantics:

- Missing validation loss **only** produces `convergence_caveated` when `requires_validation_tracking=true`.
- When `validation_policy=train_only_convergence` or `validation_metric=not_required`, absent validation loss is recorded as a `protocol_note` and does not affect `convergence_status`.
- Present validation loss is assessed for NaN/Inf and pathological trends.

### ST plugin wrappers (stgcn, grin, ignnk, dcrnn)

All four corrected variant plugins now compute `validation_loss` per epoch when `_validation_split` is present in `config`. The loss is recorded into the training history returned by `get_training_history()`.

### `_st_graph_validation.py`

New shared helper created to resolve a circular import between `GraphRuntimeProvider` and the spatiotemporal services package.

### `st_training_adequacy_service.py`

Backfill path updated to normalise validation metadata from `runtime_summary.json` using the new schema fields.
