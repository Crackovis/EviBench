# Thesis Workflow — Dashboard → Storyboard → Gate → Export

The thesis workflow is a dedicated evidence path built on top of the canonical
ImputeBench route. It is designed to transform raw experiment results into
defensible, thesis-grade evidence ready for export.

## Where it fits

The canonical workflow (Data & Algorithms → Experiment Runs → Results Navigator →
Comparison Studio) produces **results and comparisons**. The thesis workflow takes
those outputs and elevates them to **evidence**:

```mermaid
flowchart LR
    C[Comparison Studio] --> D[Dashboard]
    D --> S[Storyboard]
    S --> G[Gate]
    G --> E[Export]
```

## The three thesis pages

### 🧪 Thesis Evidence Dashboard

**Role** — Central evidence-control surface. It is the entry point to the thesis
workflow and provides a bird's-eye view of evidence readiness across four
dimensions:

| Dimension | What it tracks |
|---|---|
| **Training Evidence** | Loss curves, checkpoint summaries, best-loop selection per DL result |
| **Official Benchmarks** | Benchmark contracts, mask banks, materialization status |
| **Artifact Availability** | Predictions, training histories, checkpoints — what exists and what is missing |
| **Export Readiness** | Whether each comparison or result cohort is ready for thesis export |

The dashboard surfaces **action items** with direct handoffs to the relevant page:

- Missing training evidence → **Experiment Runs** (re-execute or recover)
- Incomplete benchmark materialization → **Comparison Studio** (materialize)
- Ready for narrative assembly → **Result Storyboard**
- Ready for final check → **Evidence Completeness Gate**

**Entry point** : Page `15_Thesis_Evidence_Dashboard` in the Streamlit app.

---

### 📖 Result Storyboard

**Role** — Scientific narrative planning. The storyboard assembles evidence from
comparisons or result cohorts into a structured, exportable narrative document.

A storyboard captures:

- **Context** — which dataset, benchmark contract, and algorithms are in scope
- **Evidence sections** — training evidence, metric tables, visual comparisons,
  statistical tests, caveats
- **Narrative annotations** — scientific commentary that accompanies each section
- **Export target** — thesis chapter, paper, or standalone reproducibility bundle

Storyboards can be created from:

- A **Comparison Studio spec** (full comparison context with benchmark identity)
- A **result cohort** (ad-hoc group of results from Results Navigator)

**Entry point** : Page `16_Result_Storyboard` in the Streamlit app.

**Handoffs received from** : Thesis Evidence Dashboard, Comparison Studio,
Results Navigator.

**Handoffs sent to** : Evidence Completeness Gate.

---

### 🚦 Evidence Completeness Gate

**Role** — Final guardrail before thesis export. Evaluates storyboards,
comparisons, or result cohorts against completeness rules and issues a verdict.

The gate operates at four **profiles** (increasing strictness):

| Profile | Rules enforced | Use case |
|---|---|---|
| `diagnostic` | Minimal — structural checks only | Quick sanity check during development |
| `reportable` | Standard — metrics, artifacts, basic completeness | Conference paper or interim report |
| `thesis_ready` | Full — benchmark identity, training evidence, reproducibility | Thesis chapter submission |
| `reproducibility_bundle` | Maximum — includes environment, seeds, exact artifact hashes | Peer-review reproducibility pack |

**Verdict outcomes** :

| Verdict | Badge | Meaning |
|---|---|---|
| `PASS` | 🟢 thesis_ready | All rules satisfied |
| `PASS_WITH_CAVEATS` | 🟠 reportable_with_caveats | Usable with documented caveats |
| `FAIL_INCOMPLETE` | ⚪ incomplete | Missing required evidence |
| `FAIL_BLOCKED` | 🔴 blocked | Structural blocker (e.g., missing benchmark identity) |

**Entry point** : Page `17_Evidence_Completeness_Gate` in the Streamlit app.

**Handoffs received from** : Result Storyboard, Thesis Evidence Dashboard.

---

## CLI integration

Every page action has a CLI equivalent for scripting and CI:

```bash
# Evaluate a comparison spec for thesis readiness
imputebench evidence gate comparison spec_abc --profile thesis_ready

# Evaluate a storyboard JSON
imputebench evidence gate storyboard sb_def.json --profile reproducibility_bundle

# Batch gate across all comparisons
imputebench evidence gate dashboard --profile reportable --limit 100

# Generate all thesis evidence packs
```

## Recommended sequence

1. **Dashboard** — review evidence posture, identify gaps
2. **Comparison Studio** — materialize any incomplete official comparisons
3. **Storyboard** — assemble the scientific narrative from ready evidence
4. **Gate** — run the final completeness check
5. **Export** — produce thesis-ready figures, tables, and narrative bundles

Each step surfaces specific action items; you do not need to memorize the whole
sequence before becoming productive. Start at the Dashboard and follow the
visible next steps.
