# EviBench Official Experiment Recipes

This folder documents reproducible experiment preparation recipes used by EviBench. The authoritative executable configuration lives in the recipe-book services; the markdown files explain the intent, object graph, and safe usage.

## Purpose

Define and document the official experiment lanes that EviBench can prepare, execute, and compare. Each lane is a coherent grid of experiment objects (mask banks, benchmark contracts, plans, comparison shells) that can be prepared in one pass by the app or the CLI.

## How this folder relates to the app

| App feature | Code reference |
|---|---|
| Recipe book | `imputebench/services/experiment_helpers/builtin_recipes.py` — official LondonAQ recipe books |
| Experiment Helpers | `app/pages/experiments/experiment_runs/planning_assets/tab.py` — Preparation Board + Pipeline |
| Official Preparation Pipeline | P9.5 automation service — bulk mask banks, contracts, plans, comparison shells |
| CLI batch preparation | `scripts/prepare_official_experiments.py` — same service as the UI |
| Plan Manager | `app/pages/experiments/experiment_runs/manager/tab.py` — execute, inspect, compare |
| Comparison Studio | `app/pages/experiments/08_Results_Navigator.py` — schema-aware comparison |

## Available experiment lanes

| Lane | Dataset | Domain | Methods | Missingness | Status | Recipe book |
|---|---|---|---|---|---|---|
| Lane 1 Temporal LondonAQ DL | LondonAQ | temporal imputation | BRITS, SAITS, GRU-D, Simple RNN/LSTM/GRU, SAITS-LC/LCH | MCAR/MAR/MNAR 0.1/0.3/0.5 | official | `official_londonaq_dl_benchmark` |
| Lane 1 Temporal LondonAQ Classical | LondonAQ | temporal imputation | Mean, Median, LOCF, LinearInterpolation, KNN | MCAR/MAR/MNAR 0.1/0.3/0.5 | official | `official_londonaq_classical_benchmark` |
| Lane 2 Spatio-Temporal LondonAQ | LondonAQ | spatio-temporal imputation | STGCN, DCRNN, GRIN, IGNNK (corrected variants) | MCAR/MAR/MNAR/spatial_block/sensor_dropout/node_holdout 0.3 | official (CLI-first, Tier-A certified) | `official_londonaq_st_benchmark` |
| Study — Dataset Diagnostics | LondonAQ | dataset characterization | Stationarity (ADF/KPSS), ARMA order selection, ACF/PACF, outlier detection | N/A | CLI-first | N/A |
| Future Temporal DL Ablation | LondonAQ | temporal imputation | DL ablations | TBD | placeholder | TBD |

## Recommended operator workflow (CLI-first)

1. Discover recipe books: `python -m imputebench temporal recipe list`
2. Inspect a recipe book: `python -m imputebench temporal recipe inspect --recipe-book official_londonaq_classical_benchmark`
3. Dry-run first: `python -m imputebench temporal experiment dry-run --recipe-book ... --tier smoke`
4. Materialize assets: `python -m imputebench temporal experiment materialize --recipe-book ... --tier a`
5. Execute core recipes first (0.1, 0.3), stress recipes second (0.5):
   `python -m imputebench temporal experiment run --recipe-book ... --tier a --skip-completed`
6. Export evidence: `python -m imputebench temporal evidence export`
7. Run gates: `python -m imputebench temporal gate run`
8. Study results: `python -m imputebench study results summarize`

## UI path (alternative)

```text
Run Plans → Planning Assets → Experiment Helpers → Official Preparation Pipeline → Prepare All Safe
```

Or step by step:

```text
Run Plans → Planning Cockpit → Planning Assets → Load template/contract → Create Plan → Execute → Results Navigator
```

## CLI path

```bash
# Dry-run DL first
python scripts/prepare_official_experiments.py --recipe-book official_londonaq_dl_benchmark --dataset <id> --algorithms brits,saits --dry-run

# Dry-run classical first
python scripts/prepare_official_experiments.py --recipe-book official_londonaq_classical_benchmark --dataset <id> --algorithms mean,median,locf,linear,knn --dry-run

# Generate assets for a recipe book
python scripts/prepare_official_experiments.py --recipe-book official_londonaq_dl_benchmark --dataset <id> --algorithms brits,saits --create-mask-banks --create-contracts
```

## Spatio-temporal LondonAQ lane (Lane 2)

The spatio-temporal lane is **CLI-first**: the `imputebench st` command group is
the orchestration authority for the entire lifecycle —
graph assets → mask banks → recipes → plans → experiment runs → evidence → gates → official certification.
GUI layers only read the materialized registry and exported reports; they never
construct ST experiments.

```bash
# Inspect the official ST recipe book (dry-run only, nothing is launched)
python -m imputebench st recipe list --tier tier_a

# Full pipeline launch (graph → mask → plan → execute → evidence) — long-running

# Readiness gates and official Tier-A campaign certification
python -m imputebench st gate --profile scientific_ready
python -m imputebench st experiment certify-official --dry-run
```

The official Tier-A campaign consists of 24 ExperimentRun containers
(4 algorithms × 6 mask families) carrying 120 evaluation cells (× 5 shared mask
realizations), certified through `st experiment certify-official`.

## DL curriculum lifecycle (dl_curriculum_v1)

The official DL recipe book (`official_londonaq_dl_benchmark`) now uses the **dl_curriculum_v1** policy:

- Training follows a deterministic curriculum-to-target schedule (e.g. 0.10 → 0.20 → 0.30 for rate 0.30).
- Checkpoint selection is performed on a **stable_validation_surface** — validation rate stays fixed at the target rate across all training loops.
- The best training-loop evidence (`runtime_summary_payload.best_training_loop`) is **required** before a DL result can support thesis claims.
- FT-DL35–38 propagated best-loop evidence into Experiment Runs, Results Navigator, and Comparison Studio.

See `evidence/TRAINING_SELECTION_EVIDENCE.md` and `evidence/EVIDENCE_REQUIREMENTS.md` for required fields.

## Evidence and readiness rules

Before trusting any result as benchmark evidence, verify:

- Benchmark contract is ready and points to a valid mask bank
- Mask bank has realizations
- Observed-only masking is enabled
- DL configuration is hydrated for DL recipes
- Training selection evidence is accepted for lifecycle DL results
- `runtime_summary_payload.best_training_loop` is present and `evidence_status == complete`
- Test metrics and prediction artifacts exist
- Comparison Studio reports compatible schema

See `evidence/EVIDENCE_REQUIREMENTS.md` for the full checklist.
