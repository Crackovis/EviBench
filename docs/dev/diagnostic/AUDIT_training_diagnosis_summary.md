# Audit — `training_diagnosis_summary` (--diagnostic-only run)

**Date:** 2026-05-10  
**Command:** `imputebench thesis training --diagnostic-only`  
**Sidecar inspected:** `docs/dev/diagnostic/data/training_diagnosis_summary.{csv,md}`  
**Artifact scan:** `data/artifacts/` (41 run dirs, 32 diagnostic, 9 official)

---

## Overall verdict

The 32 diagnostic plans all completed successfully and their training artifacts
are intact on disk.  The sidecar previously showed only 9 rows and mis-labelled
all algorithms as BRITS because of three independent bugs in
`thesis_training_cmd.py` (now fixed, see §5).

After the fixes, a re-run of `imputebench thesis training --diagnostic-only`
will produce a **32-row sidecar** correctly attributed to four algorithms.

---

## 1. Row count — 9 instead of 32 (fixed)

**Root cause:** The SQL query required
`r.training_history_path IS NOT NULL`.  Only 9 of the 32 diagnostic result
rows had this column set in the DB; the other 23 had it NULL even though the
training artifacts were written successfully to disk.

**Fix (v2026-05-10):**
- `AND r.training_history_path IS NOT NULL` removed from the SQL `WHERE` clause.
- When `training_history_path` is NULL, the code now scans
  `data/artifacts/{run_id}/*/history/training_history_*.json` directly and
  uses the most-recent file found.

**Artifact scan confirms 32 diagnostic plans available:**

| Algorithm | Plans |
|---|---|
| BRITS   | 8 (2 tensorizations × 2 windows × 2 lr) |
| GRU-D   | 8 |
| SAITS   | 8 |
| SAITS-LC| 8 |
| **Total** | **32** |

The 9 remaining runs in the artifact store are official benchmark runs
(`dl_benchmark_official_londonaq_*`) and are correctly excluded by the
`_is_diag` filter.

---

## 2. Algorithm identity — all 9 rows showed `BRITS` (fixed)

**Root cause (corrected — 2026-05-10):** Each diagnostic run was launched with
all 8 DL algorithms in its `algorithm_ids_json`, producing 8 result rows per
run (256 total for 32 plans).  The artifact store writes one checkpoint tree per
algorithm under `data/artifacts/{run_id}/{algorithm_id}/`.  The initial reading
code found the first artifact folder (`629b66a7-…` = BRITS UUID) and labelled
every row "BRITS" regardless of the plan name.

> **Note:** `alg-dl-brits` does **not** exist in the `algorithms` table.  The
> assumption of a single phantom registry ID was incorrect.  Each algorithm has
> its own correctly registered UUID in the DB.

**Fix (v2026-05-10):** In `--diagnostic-only` mode, `name` is now back-filled
from the plan name via `_ALGO_SLUG_RE`:

```
diag_londonaq_saits_lc_*  →  SAITS-LC
diag_londonaq_saits_*     →  SAITS
diag_londonaq_gru_d_*     →  GRU-D
diag_londonaq_brits_*     →  BRITS
```

**Permanent DB fix:** `scripts/db_sanitize.py --apply` (replaces the earlier
`cleanup_phantom_algorithm.py alg-dl-brits` suggestion, which targeted a
phantom that does not exist).  `db_sanitize.py` deletes the 224 cross-
contaminated result rows (7 wrong-algo rows per run × 32 runs) and narrows each
run's `algorithm_ids_json` to its single target algorithm.

## 3. `loop_index` / `selected_loop` — all `n/a` (fixed)

## 5. `best_epoch = 200` in 8/9 rows — training ceiling

All 32 plans used `max_epochs = 200`.  `convergence_epoch` (93–132 in the
9-row sample) is well below 200, meaning 95% of loss reduction was achieved
long before the epoch limit.  The models never triggered early stopping.

epoch 200.  **Recommendation for a follow-up sweep:** increase `max_epochs`
to 300–400 or add early stopping with patience 20–30 to determine whether
further training yields meaningful gains.
