# Model Selection Rationale — STGCN, DCRNN, GRIN, IGNNK

## Selection principle

The lane should include models that are:

1. representative of graph-based spatio-temporal learning;
2. explainable without excessive implementation risk;
3. suitable for controlled imputation experiments;
4. compatible with a 140-node LondonAQ grid;
5. defensible as references, not over-sold as new contributions.

## Selected models

### STGCN

**Role**: canonical graph-temporal convolution baseline.

STGCN is selected because it is a compact and widely recognized graph-temporal architecture. It combines graph convolution for spatial structure and temporal convolution for sequence dynamics.

In this lane, STGCN should be treated as a spatio-temporal representation baseline. Since it was originally designed for forecasting, its ImputeBench usage must be explicitly framed as an adaptation to masked reconstruction, not as a native imputation method.

**Best use in this lane**

- parity masks: MCAR/MAR/MNAR;
- spatial block masks;
- graph policy sensitivity.

**Main limitation**

STGCN is not imputation-native. It requires a clear masked-input / hidden-support evaluation wrapper.

---

### DCRNN

**Role**: diffusion recurrent baseline.

DCRNN is selected because it models spatial dependency as diffusion on a graph and temporal dependency through recurrent sequence modeling.

For LondonAQ, DCRNN is useful if the graph construction can be interpreted as spatial propagation, for example via distance or correlation links. If the graph is undirected, ImputeBench should expose the bidirectional diffusion view explicitly.

**Best use in this lane**

- distance graph;
- correlation graph;
- mechanism sensitivity under MCAR/MAR/MNAR.

**Main limitation**

DCRNN benefits from a meaningful directed or diffusion graph. A purely regular symmetric grid should be used carefully and documented as a controlled approximation.

---

### GRIN

**Role**: imputation-native graph model.

GRIN is selected because it is directly aligned with multivariate time-series imputation using graph neural networks. Unlike STGCN and DCRNN, it is not merely adapted from forecasting; it is designed around missing-value reconstruction in sensor networks.

**Best use in this lane**

- primary ST imputation reference;
- comparison against temporal-only DL models;
- spatial block and sensor dropout masks.

**Main limitation**

Implementation complexity may be higher than simpler graph-temporal baselines. Its plugin should be prioritized after graph asset creation and graph tensor loading are stable.

---

### IGNNK

**Role**: spatial kriging / node-holdout model.

IGNNK is selected because it targets spatio-temporal kriging: recovering signals for unsampled or unavailable sensors. This makes it valuable for node-level missingness scenarios.

**Best use in this lane**

- sensor dropout;
- node holdout;
- virtual sensor / missing station simulation.

**Main limitation**

IGNNK should not be judged only on random point-wise missingness. Its value appears most clearly when spatial nodes or sensor groups are withheld.

## Final model set

```text
STGCN
DCRNN
GRIN
IGNNK
```

## Fallback if runtime becomes too expensive

If implementation time becomes tight, keep:

```text
STGCN
GRIN
IGNNK
```

DCRNN is the first candidate to defer because it depends most strongly on having a meaningful diffusion graph policy.
