# Operational Labels

## Purpose

ImputeBench exposes datasets, algorithms, runs, results, artifacts, benchmark
contracts, and spatiotemporal objects across multiple surfaces.  Without a
shared naming contract, every page invents its own display rules and raw UUIDs
leak into the UI.

P7 formalises a platform-wide **Operational Label Contract**:

- every operator-facing object has a title, a subtitle, a compact form,
  a technical form, and optional badge and breadcrumb variants;
- raw IDs are hidden in normal mode and surfaced only in technical/debug mode;
- missing or stale references render a safe human label instead of crashing.

---

## Default rule

**Hide raw IDs.**

Normal UI:

```
London AQ · 10×14 grid
BRITS · scientific DL
MNAR 10% · observed-only
BRITS on MNAR 10% · Test
Selected checkpoint · Train · available
```

Technical / debug UI:

```
London AQ · 10×14 grid · dataset=7ad21e91
BRITS on MNAR 10% · Test · result=3f7a91c2
```

---

## Label forms

| Variant      | When to use                                  | Example                                          |
|--------------|----------------------------------------------|--------------------------------------------------|
| `compact`    | Selectbox options, narrow table cells        | `BRITS`                                          |
| `normal`     | Default cards, breadcrumbs, captions         | `BRITS · scientific DL`                          |
| `detailed`   | Result drawers, artifact panels              | `BRITS on MNAR 10% · Test · reportable · 2026-04-27` |
| `technical`  | Debug panels, evidence drawers               | `BRITS on MNAR 10% · result=3f7a91c2`            |
| `breadcrumb` | Navigation strips                            | `London AQ / Plan 004 / Test`                    |
| `badge`      | Tiny inline status markers                   | `scientific DL`                                  |

---

## Missing references

If an object cannot be found:

```
title   = "Missing <object type>"
subtitle = "<short id>"
missing = True
tone    = "danger"
```

Example: `Missing result · 3f7a91c2`

If an object exists but its references are stale:

```
title   = "<human title>"
subtitle = "stale references"
stale   = True
tone    = "warning"
```

Labels are always resilient — they never raise exceptions.

---

## Developer usage

### Current code (backward compatible)

```python
# Plain strings — works everywhere today
wb.labels.result_label(result_id)
wb.labels.run_label(run_id)
wb.labels.dataset_label(dataset_id)
wb.labels.technical_result_label(result_id)
```

### New code (rich OperationalLabel)

```python
# Rich read model with all variants
lbl = wb.operational_labels.result(result_id)
print(lbl.display)       # "BRITS on MNAR 10% · Test"
print(lbl.short)         # "BRITS on MNAR 10%"
print(lbl.with_id)       # "BRITS on MNAR 10% · Test · 3f7a91c2"
print(lbl.tone)          # "success"
print(lbl.badges)        # ("reportable", "shared benchmark")

# Generic resolver
lbl = wb.operational_labels.resolve("result", result_id)
text = wb.operational_labels.label("result", result_id, variant="compact")

# Payload-based (for already-loaded dicts)
lbl = wb.operational_labels.resolve_payload("result", result_dict)
lbl = wb.operational_labels.resolve_payload("artifact", artifact_payload)
```

### Streamlit rendering helpers

```python
from app.label_rendering import label_text, render_label, render_breadcrumb, tone_badge

# Plain string for any widget
text = label_text(lbl, variant="compact")

# Render a rich card block
render_label(lbl)

# Render breadcrumb strip
render_breadcrumb(lbl)

# Inline HTML badge
st.markdown(tone_badge("reportable", "success"), unsafe_allow_html=True)
```
