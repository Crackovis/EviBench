# Temporal Experiment CLI Philosophy

## Invariant

**CLI builds and certifies. GUI reads and displays.**

The temporal CLI is the authoritative route for temporal benchmark
experiments. The GUI (Streamlit dashboard) may display results,
comparisons, and evidence generated by the CLI, but it does not
orchestrate temporal experiments.

## Why a first-class temporal CLI?

The existing `imputebench run create/execute/status` commands provide
low-level run CRUD. They are useful but do not constitute a complete
temporal benchmark lane. A temporal benchmark lane must:

- Discover and filter official recipe books
- Materialize mask banks, benchmark contracts, and experiment plans
- Execute classical and deep-learning experiments in a unified flow
- Track idempotent execution identities
- Write event logs and progress files
- Export machine-readable and human-readable evidence
- Evaluate readiness gates
- Certify reproducible experiment campaigns

The ST lane (`imputebench st`) established this pattern for
spatio-temporal experiments. The temporal lane mirrors it for
temporal (non-spatial) imputation experiments.

## Design principles

1. **Recipe-book-driven**: The CLI consumes official recipe books from
   `imputebench/services/experiment_helpers/builtin_recipes.py`. Users
   discover, filter, and select recipes — they do not manually construct
   experiment grids.

2. **Deterministic idempotency**: Every execution unit has a deterministic
   identity. `--skip-completed` avoids re-execution. `--resume` continues
   from a progress file.

3. **Unified classical and DL**: One command (`temporal experiment run`)
   dispatches to classical or DL execution based on recipe metadata.
   No separate commands for each execution class.

4. **Machine-readable output**: All reports are available as JSON for
   downstream tooling and as Markdown for human readers.

5. **GUI-independent**: The temporal CLI has zero Streamlit imports.
   GUI pages may read and display artifacts produced by the CLI.

## Migration path

Old:

```
UI or scripts prepare and launch temporal experiments
```

New:

```
python -m imputebench temporal experiment run \
  --recipe-book official_londonaq_classical_benchmark \
  --tier a --dataset-id london_aq --skip-completed
```

The old `imputebench run create/execute/status` commands remain available
for backward compatibility. The `scripts/prepare_official_experiments.py`
script is superseded by `imputebench temporal prepare materialize`.

## Tier model

| Tier | Description | Use case |
|---|---|---|
| A | Official full benchmark recipe set | Thesis evidence, publication |
| B | Diagnostic subset | Algorithm development, debugging |
| Smoke | Minimal 1-2 algorithm / 1 mask / 1 realization | CI, quick validation |

## DL lifecycle

The `dl_curriculum_v1` lifecycle policy orchestrates:

```
train → validate → test → use (optional)
```

Train: curriculum-to-target schedule with stable validation surface.
Validate: best checkpoint selection.
Test: evaluation on hidden test support.
Use: inference artifact production.

## Relationship to other command groups

```
imputebench st          spatio-temporal benchmark orchestration
imputebench temporal    temporal benchmark orchestration
imputebench study       dataset/result/post-analysis study
imputebench run         legacy/low-level run operations
```
