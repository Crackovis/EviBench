# Temporal Experiment CLI Reference

Complete reference for the `imputebench temporal` command group — the CLI-first
orchestration surface for temporal (non-spatial) imputation benchmarks.

📖 **Philosophy & design invariants:** [Temporal_Experiment_CLI_Philosophy.md](Temporal_Experiment_CLI_Philosophy.md)

---

## Overview

```
imputebench temporal
├── recipe              Discover and inspect official recipe books
│   ├── list            List available recipe books
│   ├── inspect         Inspect a specific recipe book
│   ├── algorithms      List algorithms in a recipe book
│   ├── masks           List mask families in a recipe book
│   ├── tiers           List tiers available in a recipe book
│   └── validate        Validate recipe book integrity
├── prepare             Materialize preparation assets
│   ├── dry-run         Preview what would be created
│   ├── materialize     Create mask banks, contracts, plans
│   └── verify          Verify preparation completeness
├── experiment          Orchestrate experiment execution
│   ├── dry-run         Preview execution plan without running
│   ├── materialize     Materialize experiment plans from recipes
│   ├── run             Run the full experiment pipeline
│   ├── status          Show execution status and progress
│   ├── reset           Reset experiment state
│   ├── phase           Inspect or advance lifecycle phases
│   └── certify         Certify reproducible experiment campaigns
├── evidence            Export and inspect evidence
│   ├── export          Export evidence artifacts
│   └── inspect         Inspect evidence completeness
├── gate                Readiness gate management
│   ├── list            List available gate profiles
│   ├── run             Evaluate a gate profile
│   └── report          Generate gate report
├── preflight           Pre-execution validation
│   ├── run             Run preflight checks
│   └── study           Study preflight results
├── lifecycle           DL curriculum lifecycle management
│   ├── policies        List available lifecycle policies
│   ├── inspect         Inspect lifecycle state for a run
│   └── report          Generate lifecycle report
└── report              Human-readable reporting
    ├── readme          Generate experiment README
    └── summary         Generate execution summary
```

## Recipe Commands

> **Architecture note (v0.3.0):** Temporal recipe commands (`list`, `inspect`,
> `algorithms`, `masks`, `tiers`, `validate`) now read from the SQLite recipe
> registry. The same CLI behavior is preserved. For CRUD operations on recipe
> books (create, clone, update, delete, export, entry/algorithm management),
> use `imputebench experiment recipe`. See
> [Recipe_Book_Architecture.md](Recipe_Book_Architecture.md) for architecture
> details.

### `imputebench temporal recipe`

Inspect official recipe books without launching any execution.

| Command | Description |
|---|---|
| `list [--tier <tier>]` | List available recipe books, optionally filtered by tier |
| `inspect <recipe_book_id>` | Show full recipe book details as JSON |
| `algorithms <recipe_book_id>` | List algorithms defined in a recipe book |
| `masks <recipe_book_id>` | List mask families defined in a recipe book |
| `tiers <recipe_book_id>` | List tiers available in a recipe book |
| `validate <recipe_book_id>` | Validate recipe book integrity and consistency |

```bash
# List all recipe books
imputebench temporal recipe list

# List only Tier A recipes
imputebench temporal recipe list --tier a

# Inspect the classical benchmark recipe book
imputebench temporal recipe inspect official_londonaq_classical_benchmark

# See which algorithms are in the DL recipe book
imputebench temporal recipe algorithms official_londonaq_dl_benchmark

# List mask families for a recipe book
imputebench temporal recipe masks official_londonaq_classical_benchmark

# Validate a recipe book before use
imputebench temporal recipe validate official_londonaq_dl_benchmark
```

## Prepare Commands

### `imputebench temporal prepare`

Materialize mask banks, benchmark contracts, and experiment plans from recipe books.

| Command | Description |
|---|---|
| `dry-run --recipe-book <id> --dataset-id <id> [--tier <tier>] [--algorithms <list>] [--json]` | Preview what would be materialized |
| `materialize --recipe-book <id> --dataset-id <id> [--tier <tier>] [--algorithms <list>] [--skip-completed]` | Create mask banks, contracts, plans |

# Dry-run: see what would be created for the classical benchmark
imputebench temporal prepare dry-run \
  --recipe-book official_londonaq_classical_benchmark \

## Experiment Commands

### `imputebench temporal experiment`

Orchestrate the full experiment lifecycle: plan, execute, monitor, and certify.

| Command | Description |
|---|---|
| `dry-run --recipe-book <id> --dataset-id <id> [--tier <tier>] [--algorithms <list>] [--json]` | Preview execution plan without launching runs |
| `materialize --recipe-book <id> --dataset-id <id> [--tier <tier>] [--json]` | Materialize experiment plans from recipes |
| `run --recipe-book <id> --dataset-id <id> [--tier <tier>] [--algorithms <list>] [--families <list>] [--rates <list>] [--skip-completed] [--resume] [--event-log <path>] [--progress-file <path>]` | Run the full experiment pipeline |
| `status [--recipe-book <id>] [--json]` | Show execution status and progress |
| `reset --recipe-book <id> [--tier <tier>] [--confirm]` | Reset experiment state (requires confirmation) |
| `phase <run_id> [--advance] [--set <phase>]` | Inspect or advance lifecycle phases |
| `certify --recipe-book <id> [--tier <tier>] [--dry-run]` | Certify reproducible experiment campaigns |

```bash
# Dry-run: preview what experiments will run
imputebench temporal experiment dry-run \
  --recipe-book official_londonaq_classical_benchmark \
  --dataset-id london_aq \
  --tier a

# Materialize experiment plans (no execution)
imputebench temporal experiment materialize \
  --recipe-book official_londonaq_classical_benchmark \
  --dataset-id london_aq \
  --tier a

# Run the full pipeline (materialize + execute)
python -m imputebench temporal experiment run \
  --recipe-book official_londonaq_classical_benchmark \
  --dataset-id london_aq \
  --tier a \
  --skip-completed

# Run with event logging and progress tracking
python -m imputebench temporal experiment run \
  --recipe-book official_londonaq_dl_benchmark \
  --dataset-id london_aq \
  --tier a \
  --skip-completed \
  --event-log data/logs/temporal_events.jsonl \
  --progress-file data/logs/temporal_progress.json

# Resume from a progress file after interruption
python -m imputebench temporal experiment run \
  --recipe-book official_londonaq_dl_benchmark \
  --dataset-id london_aq \
  --resume

# Check execution status
imputebench temporal experiment status --recipe-book official_londonaq_dl_benchmark
imputebench temporal experiment status --json

# Inspect lifecycle phase of a specific run
imputebench temporal experiment phase run_xxxxxxxx

# Certify a campaign (dry-run first)
imputebench temporal experiment certify \
  --recipe-book official_londonaq_classical_benchmark \
  --tier a \
  --dry-run

# Certify a campaign (for real)
imputebench temporal experiment certify \
  --recipe-book official_londonaq_classical_benchmark \
  --tier a
```

## Exit Codes

| Code | Meaning |
|---|---|
| 0 | Success — all operations completed without error |
| 1 | General error — operation failed |
| 2 | Validation error — recipe book or assets failed validation |
| 3 | Preflight failure — environment not ready for execution |
| 4 | Gate failure — readiness gate not passed |
| 5 | Partial completion — some executions succeeded, some failed (check progress file) |
| 6 | Certification failure — campaign does not meet certification criteria |

## Backward Compatibility

The legacy `imputebench run create/execute/status` commands remain fully functional
and unchanged. The `scripts/prepare_official_experiments.py` script continues to work
but is superseded by `imputebench temporal prepare materialize` for new workflows.

Existing experiment data (mask banks, benchmark contracts, plans, results) produced
by either route is compatible with both interfaces.
